# 채널: 쓰레드 (Threads)

X와 결이 비슷하고 **한국 사용자 비중이 크다.** 일상 후기, 특정 커뮤니티의 실시간 반응, 밈이 산다.
Meta 계열이라 로그인 벽이 있다. 공개 게시물만 쫓는다. ([access-tiers.md](access-tiers.md) 참조)

## 접근 현실 (실측 2026-11-21)

| 경로 | 결과 |
|---|---|
| 인앱 브라우저 | **본문 확인(11-22).** 로그인 없이 공개 프로필의 소개, 팔로워 수, 최근 게시물과 반응 수가 보였다. `threads.net`은 `threads.com`으로 리다이렉트된다 |
| Claude in Chrome | 열림(제목만 확인) |
| `WebFetch` | "unable to fetch from www.threads.net" |
| `WebSearch` | `site:threads.net` 결과 0건. 쓰레드를 다룬 블로그 글만 잡혔다 |

**도메인은 이제 `threads.com`이다.** URL은 `https://www.threads.com/@<핸들>`,
게시물은 `https://www.threads.com/@<핸들>/post/<ID>` 형식으로 쓴다.

## 긁는 순서 (되는 것부터)

1. **핸들을 알면 인앱 브라우저로 바로 연다.** `threads.com/@<핸들>`을 열어 렌더링된 본문과 공개 게시물을
   읽는다. 로그인 없이 공개 프로필은 보인다.
2. **게시물을 찾아야 하면 간접 발견.** `WebSearch`는 쓰레드 원글을 거의 색인하지 않는다.
   `[키워드] 쓰레드`, `[키워드] threads`로 쓰레드 화제를 정리한 블로그·기사를 먼저 찾고, 거기서
   핸들과 게시물 URL을 주워 1번으로 연다. `site:threads.com [키워드]`도 한 번은 시도한다.
3. **로그인된 크롬.** 쓰레드 내부 검색이나 로그인해야 보이는 피드가 꼭 필요하면 사용자 허락 하에 로그인된
   크롬(claude-in-chrome)으로 **읽기만** 한다.

`WebFetch`는 쓰지 않는다. 도구 차단이라 다시 시도해도 같다.

## 요령

- 쓰레드는 검색 엔진 색인이 X보다 얇다. 그래서 **블로그·커뮤니티에 "쓰레드에서 화제" 정리 글**이
  오히려 더 많을 때가 있다. 교차로 훑는다.
- 로그인·팔로우 전용 게시물은 건드리지 않고 "쓰레드 로그인 필요"로 보고한다.
