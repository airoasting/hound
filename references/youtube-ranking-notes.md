# 랭킹·필터 설계 근거

`scripts/yt_collect.py`의 판단 로직을 왜 그렇게 짰는지, 어떻게 조정하는지 정리한다.

## 1. 왜 총 조회수를 기본으로 두는가

"이번 주 top 10 영상"이라는 요청의 관습적 의미는 **그 기간 가장 많이 본 영상**이다.
그래서 기본 정렬은 총 조회수(`--rank views`)다.

한계: 7일 창은 게시 1일 된 영상과 6일 된 영상을 섞는다. 늦게 올라온 영상은 조회수를
쌓을 시간이 짧아 구조적으로 불리하다. 이를 보완하려고 두 보조 지표를 함께 계산한다.

- **조회 속도(velocity)** = 총 조회수 ÷ (게시 후 경과 일수). "하루당 몇 회 보는가".
  신선도·화제성을 본다. `--rank velocity`로 주 정렬로 승격 가능.
- **참여율(engagement_rate)** = (좋아요 + 댓글) ÷ 조회수. 조회수 대비 반응 강도.
  낚시성·자동재생 조회수와 진짜 화제를 구분하는 단서. 동점 처리와 품질 판단에 쓴다.

정렬 키는 `(주지표, 조회속도, 참여율)` 순 내림차순이라 주지표가 같을 때 신선하고
반응 강한 쪽이 앞선다.

## 2. 기간 창을 두 번 거르는 이유

유튜브 검색의 업로드 기간 필터(sp 파라미터)는 "이번 주/이번 달" 같은 coarse 단위만 있고,
가끔 무시되기도 한다. 그래서:

1. 검색 단계 — sp 필터로 대략 최근 영상 위주 후보를 모으고(속도),
2. 확정 단계 — 각 영상의 정확한 게시 시각(timestamp)으로 `지금 - N일` 창을 다시 적용한다(정확도).

이 이중 필터 덕에 "지난 3일"처럼 sp에 없는 임의 창도 정확히 처리된다.

## 3. 관련성 필터 (topic-packs.json)

- **include**: 제목·채널·설명(소문자) 중 하나라도 이 어휘를 포함해야 통과. 로봇 팩은
  robot/robotic/humanoid/보스턴다이내믹스/옵티머스 등.
- **exclude**: 이 어휘가 있으면 무조건 탈락. 동음이의를 막는다(Mr. Robot, Roblox,
  Robot Chicken, "Robot Rock" 음원, 댄스 튜토리얼 등).
- 매칭은 부분일치라 과잉 차단에 주의. exclude는 최소로 유지하고, 애매한 컷은
  모델 큐레이션(SKILL 3단계)에서 처리한다.

## 4. 채널 중복 제거

한 채널이 같은 주에 여러 편을 올려 순위를 도배하면 "인기 지도"의 가치가 떨어진다.
기본 채널당 2편(`--per-channel 2`). 특정 채널 집중 분석이면 값을 키우거나 1로 낮춘다.

## 5. 쇼츠 처리

기본은 포함(짧아도 조회수 폭발이 흔함). 롱폼만 보려면 `--no-shorts`(60초 미만 제외).
리포트에는 항상 길이를 표기해 사용자가 구분하게 한다.

## 6. 조정 치트시트

| 원하는 것 | 옵션 |
|-----------|------|
| 지금 뜨는(신선도) 우선 | `--rank velocity` |
| 한국 영상 위주 | `--region KR --lang ko` |
| 롱폼만 | `--no-shorts` |
| 후보를 더 넓게 | `--per-query 30 --max-candidates 50` |
| 채널 도배 완전 차단 | `--per-channel 1` |
| 잡음 영상 컷 | `--min-views 5000` |
| 키로 정밀 수집 | `export YOUTUBE_API_KEY=...` 후 그대로 실행 |
