# 채널: 링크드인 (LinkedIn)

인물 경력·회사 정보·채용·B2B 인사이트가 산다. 공개 프로필·회사 페이지·채용 공고는 로그인 없이도
상당 부분 읽힌다. ([access-tiers.md](access-tiers.md) 참조)

## 접근 현실 (실측 2026-11-21~22)

| 경로 | 결과 |
|---|---|
| 인앱 브라우저 | **본문 확인.** 공개 회사 페이지에서 회사 소개, 직원 수(6,487명), 채용공고 메뉴가 보였다 |
| Claude in Chrome | 열림(제목만 확인) |
| `WebFetch` | 403 Forbidden |

링크드인이 `WebFetch`에 403을 돌려준 페이지를 Jina Reader 같은 리더로 다시 열지 않는다. 사이트가 막은
요청을 다른 경로로 돌아가 여는 일이다.

## 긁는 순서 (되는 것부터)

1. **웹 검색으로 발견.** `WebSearch`로 `site:linkedin.com/in [이름 회사]`(인물),
   `site:linkedin.com/company [회사명]`(회사), `site:linkedin.com/jobs [직무 지역]`(채용).
2. **인앱 브라우저로 공개 페이지를 연다.** 회사 소개, 직원 수, 공개 프로필 요약이 렌더링된 화면에 보인다.
   `get_page_text`가 비면 `read_page`로 `main` 영역만 읽는다([access-tiers.md](access-tiers.md)의 크롬 절차와 같다).
3. **로그인 벽.** 인맥·비공개 활동·전체 경력은 로그인이 필요하다. 사용자 허락 하에 로그인된 크롬으로
   **읽기만** 하거나 "링크드인 로그인 필요"로 보고한다.

`WebFetch`는 403이라 쓰지 않는다.

## 요령

- 회사·직무 조사는 링크드인(회사 페이지·공고) + 뉴스 + 회사 공식 페이지를 교차한다.
- 채용 조사는 여러 공고를 모아 공통 요구사항·연봉대를 뽑는다.
- 인물은 **공개 직무 이력**까지만 다룬다. 회사가 발표하거나 언론이 보도한 직책·경력은 확인해도 된다.
  사생활, 연락처, 가족, 비공개 활동처럼 공적 역할과 무관한 정보는 찾지도, 여러 채널에서 짜맞추지도 않는다
  ([SKILL.md](../SKILL.md)의 "지키는 원칙").
