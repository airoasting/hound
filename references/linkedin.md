# 채널: 링크드인 (LinkedIn)

인물 경력·회사 정보·채용·B2B 인사이트가 산다. 공개 프로필·회사 페이지·채용 공고는 로그인 없이도
상당 부분 읽힌다. ([access-tiers.md](access-tiers.md) 참조)

## 접근 현실 (실측 2026-11-21)

| 경로 | 결과 |
|---|---|
| 인앱 브라우저 | 공개 회사 페이지가 열린다 |
| Claude in Chrome | 열린다 |
| `WebFetch` | 403 Forbidden |
| Jina Reader | 키 없이 200을 준다(example.com으로 확인). 링크드인 페이지에는 아직 시험하지 않았다 |

## 긁는 순서 (되는 것부터)

1. **웹 검색으로 발견.** `WebSearch`로 `site:linkedin.com/in [이름 회사]`(인물),
   `site:linkedin.com/company [회사명]`(회사), `site:linkedin.com/jobs [직무 지역]`(채용).
2. **인앱 브라우저로 공개 페이지를 연다.** 회사 소개, 팔로워 수, 공개 프로필 요약, 채용 공고가 렌더링된
   화면에 보인다. `get_page_text`가 비면 `read_page`로 `main` 영역만 읽는다
   ([access-tiers.md](access-tiers.md)의 크롬 절차와 같다).
3. **Jina Reader(보조).** `https://r.jina.ai/<링크드인URL>`. 지금은 키 없이도 응답하지만 링크드인에서 되는지는
   확인하지 않았다. 브라우저가 막힌 환경에서만 시도한다.
4. **로그인 벽.** 인맥·비공개 활동·전체 경력은 로그인이 필요하다. 사용자 허락 하에 로그인된 크롬으로
   **읽기만** 하거나 "링크드인 로그인 필요"로 보고한다.

`WebFetch`는 403이라 쓰지 않는다.

## 요령

- 인물 검증은 링크드인(경력) + 뉴스(활동) + 회사 페이지를 교차한다.
- 채용 조사는 여러 공고를 모아 공통 요구사항·연봉대를 뽑는다.
- 특정 개인의 정보를 여러 채널에서 짜맞추지 않는다(SKILL 가드레일).
