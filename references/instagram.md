# 채널: 인스타그램

프로필·최근 게시물·해시태그·탐색 피드에 브랜드·인물·트렌드·비주얼이 산다. Meta 계열이라
로그인 벽이 강하다. **공개 범위만** 쫓는다. ([access-tiers.md](access-tiers.md) 참조)

## 접근 현실 (실측 2026-11-21)

| 경로 | 결과 |
|---|---|
| `WebFetch` | 공개 프로필 HTML이 온다(게시물 일부, 로그인·가입 링크 포함) |
| 인앱 브라우저 | 공개 프로필이 열린다 |
| Claude in Chrome | 열린다. 로그인 상태면 피드·탐색도 보인다 |
| `yt-dlp` | 공개 릴스 단건은 쿠키 없이 된다. 프로필·피드는 실패한다(2026-10-08 실측) |

## 긁는 순서 (되는 것부터)

1. **웹 검색으로 발견.** `WebSearch`로 `site:instagram.com [키워드]` 또는 `[사용자명] instagram`.
   공개 프로필·게시물·해시태그 페이지가 잡힌다.
2. **공개 프로필/게시물은 `WebFetch`.** 공개 계정의 소개·게시물 캡션·해시태그가 보인다. 가장 빠르다.
3. **릴스 숫자는 `yt-dlp`.** 공개 릴스 URL이면 `yt-dlp -J --skip-download`로 좋아요·댓글·게시일·설명을
   받는다([access-tiers.md](access-tiers.md)의 "로그인 벽 수집 순서").
4. **`WebFetch`가 비면 인앱 브라우저.** 렌더링된 공개 프로필을 읽는다.
5. **로그인된 크롬.** 최근 게시물 피드·탐색은 대부분 로그인을 요구한다. 사용자 허락 하에 로그인된
   크롬(claude-in-chrome)으로 **읽기만** 수행한다.

Jina Reader(`https://r.jina.ai/<URL>`)는 지금 키 없이도 응답한다(2026-11-21). 인스타그램에서는 시험하지
않았으니 위 경로가 모두 막혔을 때만 보조로 쓴다.

## 요령 · 가드레일

- 특정 개인의 사생활 추적 금지. 브랜드·공개 크리에이터·해시태그 트렌드까지만.
- 비공개 계정은 건드리지 않고 "비공개 계정"으로 보고한다.
- 비주얼이 핵심이면 이미지 URL을 회수해 함께 물어온다.
