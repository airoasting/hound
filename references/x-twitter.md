# 채널: X (트위터)

실시간 여론, 속보, 당사자의 직접 발언이 사는 곳. 대신 **X 소유 도메인은 봇 접근이 막혀 있고**
타임라인·검색은 로그인 벽 뒤다. 특정 트윗 하나를 읽는 데는 확실한 우회로가 있으니 그걸 쓴다.
([access-tiers.md](access-tiers.md) 참조)

## 접근 현실 (직접 확인)

- **`WebFetch`는 X 소유 도메인(x.com, publish.x.com)에서 402로 막힌다.** 서드파티 미러는 통과한다.
- **Nitter는 죽었다.** nitter.net(빈 셸)·xcancel.com(브라우저 검증 챌린지)·poast(503) 등 공개
  인스턴스는 자동화로 못 뚫는다(2024년 X가 게스트 계정을 없앤 여파). **의존하지 않는다.**
- **검색·타임라인·보호 계정은 로그인 벽.** 이건 실제 세션이라야 열린다.

## 긁는 순서 (사다리)

1. **트윗 발견.** `WebSearch`로 `[키워드] X` 또는 인물·핸들을 넣어 트윗 URL/ID를 찾는다. 뉴스·블로그가
   특정 트윗을 인용한 경우도 많으니 거기서 URL을 주워도 된다.
2. **단일 트윗 읽기 — fxtwitter JSON API(정공법).** 트윗 URL에서 핸들과 status ID를 뽑아
   `https://api.fxtwitter.com/<핸들>/status/<ID>`를 `WebFetch`로 연다. 서드파티 도메인이라 402를 받지
   않고, **본문 전문 + 좋아요·리트윗·댓글·조회수 + 작성자(팔로워 수)**까지 JSON으로 온다. 무키·무계정.
   - 죽었으면 `https://api.vxtwitter.com/<핸들>/status/<ID>`로 갈아탄다.
   - 텍스트·작성자만 있으면 되면 `publish.x.com/oembed?url=<트윗URL>`도 되지만, 이건 X 도메인이라
     **`WebFetch`로는 402다. Bash `curl`(브라우저 UA)로만** 열리고 engagement 숫자는 안 준다.
   서드파티 미러는 제3자 운영이라 가용성 리스크가 있으니 fxtwitter → vxtwitter → oEmbed(curl) 순으로 내려간다.
3. **검색·타임라인·보호 계정 — 실제 크롬 세션.** 키워드 검색이나 한 계정의 흐름 전체는 위 API로 안
   된다. 꼭 필요하면 사용자 허락 하에 로그인된 크롬(claude-in-chrome)으로 **읽기만** 한다. 로그인을
   요구하는 지점에서 **멈춘다.**

## 검색어 요령

- 한국 이슈는 한국어로, 글로벌 이슈·해외 인물은 영어로 각각 판다.
- 해시태그(`#키워드`)와 인용구를 그대로 넣으면 특정 반응 덩어리를 잡기 좋다.
- 속보성은 시점을 좁혀("2026 7월 ...") 최근 것만 걸러낸다.

## 챙길 숫자

fxtwitter/vxtwitter 응답에서 **팔로워 수, 좋아요·리트윗·인용·댓글 수, 조회수**를 함께 회수한다.
장문 트윗은 `is_note_tweet`로 구분되고 커뮤니티 노트도 응답에 담긴다.

## 로그인 벽 (반드시 지킨다)

- 단일 공개 트윗까지만 위 방법으로. 로그인해야 보이는 타임라인·비공개·보호 계정은 **건드리지 않는다.**
- 벽을 만나면 "여기부터는 X 로그인이 필요하다"고 보고하고, 그 이슈를 다룬 뉴스·블로그로 채널을 갈아타
  우회 정보를 찾는다.
